# 09 · i18n

## Setup

`flutter_localizations` + `gen-l10n`. Files: `lib/l10n/app_en.arb` (source
of truth), `app_vi.arb`, `app_ja.arb`. Locale resolution: setting
`language` — `system` maps through supported locales with `en` fallback.

**The setting reached `MaterialApp` at M3 and not before.** From M1 the app set
`supportedLocales` and never a `locale`, so choosing a language wrote
`settings.json` and changed nothing on screen. `system` is `null`, which is
what makes Flutter resolve against the platform and fall back to
`supportedLocales.first`.

## Rules

1. Every user-facing string is an ARB key (CLAUDE.md rule 4) — including
   menu items, tooltips, dialogs, notices, placeholder cards ("Raw HTML
   (not rendered)", "MDX · {n} imports hidden").
2. No sentence assembly by concatenation; use placeholders and ICU plurals
   (`{count, plural, …}`) — Vietnamese and Japanese word order will break
   concatenated English fragments.
3. Key naming: `feature_element_purpose` camel-cased per gen-l10n norms,
   e.g. `readerCopyCodeTooltip`, `sidebarMissingBadge`.
4. Dates/numbers via `intl` with the active locale.
5. `en` merges first; `vi`/`ja` may trail within a PR train but must be
   complete before a release tag (release checklist, doc 15).
6. Repo documentation stays English-only.

## Layout tolerance

Vietnamese runs ~20–30% longer than English; Japanese is denser but taller.
UI must tolerate both: no fixed-width buttons around text, ellipsis +
tooltip for paths, menu bar tested in all three locales (part of the M3
DoD).

**Closed at M3, as a test rather than an eyeball.**
`test/l10n/tri_locale_layout_test.dart` pumps every surface M3 added — the
shell, all three menus, Settings, the quick switcher, the search panel, the
update banner, the empty state, the missing-file body — in all three locales at
a 1024×720 window, and fails on a `RenderFlex` overflow. A surface that fits in
English and bursts in Vietnamese is catchable that way, and is not catchable by
any assertion about behaviour. It cannot see typography or whether a sentence
reads well; that stays the maintainer's visual pass.

`test/l10n/arb_parity_test.dart` guards the other half. `l10n_untranslated.json`
already fails the build on a *missing* key; what it cannot see is a key present
because somebody pasted the English in, a translation that dropped a
placeholder and will throw the first time it is formatted, a duplicate key
(which a JSON parser silently resolves in favour of the last one — it happened
once during M3), or two menus claiming the same `Alt` letter.
